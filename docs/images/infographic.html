Burnout-as-a-Service — Algorithm Pipeline

Deterministic services compute all metrics • Pre-pass guarantees the drop • AI agents only rebalance & explain, never decide • Every agent has a fallback • Timezone-aware after-hours

INGESTION

number, title, body, labels[], assignees[],
createdAt, updatedAt, state, milestone
Nested: Label(name) • Assignee(login) • Milestone(title, dueOn)

StorageConcurrentHashMap<String, CachedIssues>

Lost on restart — re-seed via /demo/api/seed or re-sync via MCP

Data Sources

  • MCP sync — authenticated via GitHub Bearer token, schema v1
  • Public API — /demo/api/sync, rate limit: 1 per repo per 5 min
  • Seed endpoint — POST /demo/api/seed (no auth, camelCase fields)

SyntheticTimeResolver (demo label override)

demo:touched-today • demo:after-hours • demo:stale-14d • demo:friday
Golden rule: if ANY demo:* label exists → never consult real timestamps

CHAOS METRICS (runs first)

ChaosMetricsService — score 0–10 (5 × 2 pts)

mysteryMeat ≥ 3 → +2  |  unresolvedUrgent ≥ 3 → +2
touchedRecently ≥ 6 (60 min window) → +2
afterHoursSignal → +2  |  distinctLabels ≥ 12 → +2

ChaosBucket Thresholds (ordinal × 10 = stress pts)

≤ 2 LOW(0)  |  ≤ 5 MEDIUM(1)  |  ≤ 8 HIGH(2)  |  > 8 CRITICAL(3)

After-Hours Detection (timezone-aware)

Working hours: 9 AM – 6 PM in user's timezone (tz param)
Weekends (Sat/Sun) always count as after-hours
Default zone: Africa/Johannesburg (configurable via demo.clock.zone)

SyntheticTimeResolver precedence

demo:* label present → use synthetic signal, skip real timestamp
No demo label → consult actual updatedAt / createdAt

CLASSIFICATION & COMPLIANCE

IssueClassifierService — 4 Buckets (first match wins)

  • DEEP_WORK priority:critical/high, architecture, security, deep-work, hours>2, epic/feature regex
  • QUICK_WIN good-first-issue, quick-win, low-hanging-fruit, trivial; hours<0.5 + clear scope; enhancement + body<500
  • MAINTENANCE dependencies, documentation, triage, chore, refactor, tech-debt, ci, devops, maintenance
  • DEFERRED default fallback

ComplianceService — score 100 → 0 (8 violations)

CRITICAL −25 MULTIPLE_DEEP_WORK • EXCESSIVE_CTX_SWITCH(>5) • TOTAL_OVERLOAD(>7)
WARNING −10 QUICK_WIN_OVERLOAD(>3) • MAINTENANCE_OVERLOAD(>3) • UNCLEAR_QUICK_WINS
INFO −5 NO_DEEP_WORK • DEFERRED_BACKLOG_GROWING(>5, 14d stale)

DayStructure (3-3-3 — classification runs again here)

MAX_DEEP_WORK = 1  |  MAX_QUICK_WINS = 3  |  MAX_MAINTENANCE = 3
MAX_ACTIVE = 1 + 3 + 3 = 7  |  Remaining → DEFERRED

WORLDSTATE & STRESS (6-Component Breakdown)

12 Capped Variables

deferred ≤ 10 • urgentUnassigned ≤ 10 • contradictory ≤ 5
touchedToday ≤ 10 • afterHours ≤ 5 • stale ≤ 10
mysteryMeat ≤ 10 • unclearQuickWins ≤ 5

Stress Score — 6 breakdown components, max 100

Workload (0–40): assigned > 7 → min(20, (n−7)×4)
  deepWork > 1 → +(n−1)×10  |  deepWork == 0 && total > 0 → +5
Chaos (0–30): chaosBucket.ordinal × 10
Context Switching (0–15): touched > 5 → min(15, (n−5)×3)
Clarity (0–10): min(10, mysteryMeat × 2)
Sustained (0–15): min(15, consecutiveHighDays × 5)
After Hours (0–10): min(10, afterHoursIssues × 5)

  −urgent · −priority:critical · −priority:high · +triaged,backlog

  no timestamp rewriting — real after-hours / touched-today signals preserved (acknowledge-don't-erase)

Strategy: SUMMARY • maxAgentsInvocations: 15 • retries: 2
